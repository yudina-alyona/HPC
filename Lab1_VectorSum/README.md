# Описание проделанной работы

Лабораторная работа выполнена на языке Python в среде Google Colab с использованием библиотек NumPy, Numba и CUDA.

**Версия для CPU**

Функция vector_sum_cpu реализует последовательное суммирование элементов вектора с помощью обычного цикла. Каждый элемент по очереди прибавляется к результирующей переменной.

**Версия для GPU**

Функция vector_sum_gpu использует CUDA для параллельного суммирования. В ядре vector_sum_gpu_kernel каждый поток обрабатывает один элемент вектора. С помощью cuda.grid(1) каждому потоку назначается уникальный индекс, что позволяет распределить элементы вектора между всеми потоками. Затем внутри каждого блока выполняется алгоритм попарное сложение, после чего результаты всех блоков суммируются.

**Параллелизация**

Было распараллелено суммирование элементов вектора. В последовательной версии на CPU каждый элемент складывается по очереди, что для вектора из миллиона элементов требует миллиона операций. На GPU все эти операции выполняются одновременно с помощью потоков.

# Результаты экспериментов

Было проведено суммирование векторов различной длины: 1000, 5000, 10000, 50000, 100000, 500000 и 1 000 000 элементов. Полученные результаты представлены в таблице:

| Размер вектора | Время на CPU (с) | Время на GPU (с) | Ускорение |
|----------------|------------------|------------------|-----------|
| 1000           | 0.000456         | 0.000905         | 0.50      |
| 5000           | 0.003562         | 0.000820         | 4.35      |
| 10000          | 0.007681         | 0.001356         | 5.66      |
| 50000          | 0.013515         | 0.000574         | 23.55     |
| 100000         | 0.015345         | 0.000625         | 24.54     |
| 500000         | 0.080610         | 0.001542         | 52.27     |
| 1000000        | 0.166332         | 0.001684         | 98.80     |

*Анализ времени выполнения.* На CPU время растёт пропорционально размеру вектора - чем больше данных, тем дольше выполняется суммирование. На GPU время остаётся практически неизменным, поскольку добавление новых элементов распределяется между дополнительными потоками, которые работают параллельно.

*Анализ ускорения.* Для самого маленького вектора (1000 элементов) GPU работает медленнее CPU - ускорение меньше 1. Это объясняется расходами на передачу данных и запуск ядра, которые для маленького объёма данных превышают выигрыш от параллелизации. Начиная с 5000 элементов, GPU начинает опережать CPU, а с ростом размера вектора ускорение достигает почти 100 раз для миллиона элементов.

Последовательная версия показывает хорошие результаты только для маленьких объёмов данных, где накладные расходы на запуск GPU не окупаются. Однако при работе с большими векторами (от 100 000 элементов и более) GPU демонстрирует значительное преимущество за счёт параллельной обработки данных.
