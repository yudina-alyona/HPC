**Описание проделанной работы**

В данной лабораторной работе был проведен эксперимент по сравнению времени выполнения алгоритма массового поиска подстрок на CPU и GPU с использованием CUDA для буферов данных различного размера.

**Алгоритм**

На первом этапе выполняется предварительная обработка: для каждого символа алфавита создаётся список всех вхождений этого символа в искомые подстроки. Формируется рабочая матрица R размером |N| × |H| (количество подстрок x длина буфера), которая изначально заполняется длинами соответствующих подстрок. При проходе по буферу поиска для каждого символа находятся все пары (индекс подстроки, позиция символа в подстроке), и выполняется декремент соответствующего элемента рабочей матрицы. После обработки всех символов нулевые элементы рабочей матрицы указывают на найденные подстроки и их позиции.

**CPU:** функция mass_search_CPU последовательно обрабатывает каждый символ буфера, для каждого символа находит соответствующие пары из предварительно построенной карты и уменьшает значения в рабочей матрице. Время работы зависит от размера буфера и количества подстрок.

**GPU:** функция mass_search_gpu_optimized реализована с использованием CUDA для параллельного выполнения на GPU. Каждый поток обрабатывает один символ буфера независимо от других. Для безопасного обновления общей матрицы R используются атомарные операции. Размер сетки подбирается автоматически в зависимости от длины буфера (256 потоков на блок).

Эксперимент проводится на случайно сгенерированных данных (полный 8-битный алфавит, 256 символов). Для каждого размера буфера выполняется 10 запусков для получения усреднённых значений времени выполнения.

Время на CPU постепенно растёт с увеличением размера буфера. При размере 1600 байт CPU работает примерно в 5 раз дольше, чем при 160 байтах. Время на GPU остаётся практически одинаковым (около 0.00014 секунды) независимо от размера буфера. Это главное преимущество GPU: добавление данных почти не увеличивает время обработки, потому что все символы обрабатываются параллельно.
Ускорение GPU растёт с увеличением размера данных. На маленьком буфере (160 байт) ускорение небольшое (1.83x), потому что часть времени уходит на запуск GPU и передачу данных. На большом буфере (1600 байт) GPU работает уже в 9.22 раза быстрее CPU. Результаты совпадают во всех тестах. Это означает, что CPU и GPU версии алгоритма работают правильно, и параллельные вычисления с атомарными операциями не вносят ошибок.
